# Kaji：小而美优先的模块化方向

> 分支：`docs/lean-module-host`  
> 状态：设计讨论稿，**不发版**  
> 日期：2026-07-24  
> 给 agent / 贡献者的短版约束见仓库根目录 [AGENTS.md](../../AGENTS.md)；文档目录见 [dev_docs/README.md](../README.md)。

## 真实反馈

> 「我觉得最新的更新有些加戏加太多了。本来特别小而美的，我都得去回退到上个版本去。」

这不是个例式吐槽，而是产品信号：

- 用户认的是 **小而美的菜单栏工具**，不是功能越来越多的「指挥台」。
- 强制塞进同一套体验的新能力（休息 overlay / 运动关卡 / System / Goals 等），会让早期价值感变脏。
- 「回退版本」说明：**关不掉、躲不开** 比「功能本身差」更伤。

## 我们现在的问题（不是缺平台）

当前 Kaji 的定位是：

> macOS menu bar command center for AI coding

实际交付却是 **硬绑在一起的四块面板**（Quota / Work / System / Goals）+ 越来越重的 Break 体验。结果是：

| 现象 | 后果 |
| --- | --- |
| 故事卖 AI coding rudder | 用户打开却像多功能仪表盘 |
| 状态栏几乎只讲 Quota | 其它能力占 popover 体积，却几乎不贡献「一眼」 |
| 能力默认全开、难裁剪 | 喜欢旧版的人只能回退，而不是关掉多余模块 |
| 继续往「all-in-one / 插件市场」冲 | 很容易 **再加戏**，而不是把产品变瘦 |

结论：**痛点是膨胀与不可裁剪，不是「还不够像 Ice / 还不够像插件平台」。**

## 要不要重构？

要，但 **不是大翻写，也不是为了插件商店**。

需要的是一层很薄的产品边界：

1. **默认瘦**：新用户/老用户打开，首先仍是安静的用量环（小而美）。
2. **可关掉**：Work / System / Goals / 重 Break 等，必须能一键不出现在轮播与状态栏。
3. **可组合的状态栏槽位**：只有启用的模块才能往菜单栏塞 glyph（例如 Work 倒计时）。
4. **不发版压力**：先在独立分支把方向写清楚、再小步改代码；版本号与 GitHub Release 先不动。

不需要（至少现在不需要）：

- Ice / Bartender 式「管理别人的菜单栏图标」
- 远程下载第三方插件、签名沙箱、商店
- 为了「平台感」再堆新模块

一句话：

> **模块化是为了让产品能变回去小，而不是为了让产品能无限变大。**

## 修正后的产品一句话

**Kaji 是可裁剪的 macOS 菜单栏模块主机；默认只保留最安静的那一层，其它能力按需打开。**

- 对多数 AI coding 用户：默认 = **Quota**（+ 可选的轻量 Work 倒计时，不含重 overlay）。
- 对需要节奏/系统/目标的人：自行打开对应模块。
- 「All-in-one」指 **一个壳子里按需组装**，不是 **安装后强制全家桶**。

## 模块清单（第一期只谈内置）

| ID | 默认 | Popover | 状态栏 | 备注 |
| --- | --- | --- | --- | --- |
| `quota` | **开** | 用量/成本/压力 | 双环 | 核心，尽量保持克制 |
| `work` | 关或「轻量开」 | focus/break 控制 | 可选倒计时 | 与「重 Break overlay / 运动关卡」解耦 |
| `system` | 关 | CPU/MEM/清理 | 默认不占栏 | 进阶 |
| `goals` | 关 | 每日目标/热力图 | 默认不占栏 | 进阶 |

Break 的「全屏拦住 / 强度 / 运动」视为 `work` 下的 **强度选项**，默认应偏安静；重模式必须显式打开，且关掉 `work` 时整条链路消失。

## 开发原则（本分支）

1. **Docs first**：先定边界与非目标，再动 `Sources/`。
2. **独立 tree**：本方向在 `docs/lean-module-host`（及后续 `feat/...`）推进，不直接搅 `main` 发版。
3. **不涨版本号**：在用户能「关掉加戏、回到小而美」之前，不发新 Release。
4. **增量，不重写**：优先 `Prefs.enabledModules` + popover 过滤 + status item 槽位；控制器按开关停轮询即可，不必先拆 SPM 多 target。
5. **删戏优先于加戏**：每个 PR 问一句——这是让默认更安静，还是又多了一个回不去的表面？

## 建议落地顺序（仍不发版）

1. **文档定稿**（本文件 + 英文对照 + 架构草稿）
2. **Prefs：`enabledModules`**，Settings 可开关；popover 只轮播已启用项
3. **默认配置变瘦**（至少 System/Goals 默认关；重 Break 默认关）
4. **Status bar slots**：Quota 环 + 可选 Work 倒计时
5. **关模块即停工**：关 Quota 不跑 `quota.py`；关 System 停 monitor
6. 体验稳定后，再单独讨论 README 文案与版本号

## 和此前「插件下载」想法的关系

「Quota 以后做成可下载插件」可以保留为 **远期想象**，但当前正确切片是：

- 今天：内置模块 + 开关 = **假插件、真裁剪**
- 以后：若边界稳定、真有第三方需求，再谈下载/签名

用「能下载」当第一叙事，会再次推着产品往加戏走；用「能关掉、默认很瘦」当第一叙事，才对得起那条用户反馈。

## 已拍板的默认

- Work 默认：**关**
- 老用户迁移：**首次写入仅 quota**
- 重 Break：仍在 `work` 下；关 work 则整条消失
