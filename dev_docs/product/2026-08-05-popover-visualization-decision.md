# Kaji Popover 与圆环可视化：一次没有重构的产品决策

> 日期：2026-08-05  
> 类型：产品决策记录（不是 spec，不触发实现）  
> 状态：维持现状

## 结论

Kaji 暂时不重构现有 popover 信息架构，不把所有 module 统一成圆环摘要，也不改成“一级总览 + hover 二级详情”的统一模式。

这不是否定该方向，而是判断它目前并非最关键的问题。现有设计虽然需要在不同 module 间切换，却也因此层次更分明：用户清楚自己正在进入 Quota、Goals、System 还是 Work，每个 module 都有自己的信息节奏。在没有完整视觉设计前，为统一而统一可能损失这种辨识度。

仓库继续留在 `blackblue-labs/kaji`。不另建 Organization，不转移仓库。

## 讨论从哪里开始

最初的吸引力来自一个很简单的体验目标：用户不想先判断应该点击菜单栏里的哪一个区域。理想状态下，只打开一个 Kaji，就能先看到少量信息；需要细节时，再自然进入相邻的二级 popover。

这个想法包含两层：

1. 一级只提供低负担摘要，例如 AI quota、今日 Goals、剩余磁盘与计时。
2. hover 某个摘要后，在相邻二级 popover 中查看 Goals 列表、文件分类、清理建议或 quota 细节。

它的优势是降低入口选择成本，也符合 Kaji “打开一次，先看一眼”的直觉。

## 为什么圆环看起来可以统一很多东西

圆环并不只适合连续量。只要存在明确的整体与当前值，它也可以表达离散进度：

- 磁盘：剩余空间 / 总空间。
- AI quota：剩余额度 / 周期额度。
- Goals：已完成目标 / 今日目标，例如 `1 / 6`。
- 时间：剩余时间 / 当前阶段总时间。

双层圆环尤其适合 Kaji 已有的视觉语言：尺寸小、黑白灰、一眼可读，也能同时承载两个相关尺度。因此，“离散数据不能用圆环”不是否定该方案的理由。

## 为什么最后仍然不改

统一圆环会降低入口摩擦，但也可能降低 module 之间的辨识度。AI quota、Goals、System 和 Work 如果都变成相似的环，用户看到的首先是统一形式，而不是不同任务的性质。

现有设计的 trade-off 恰好相反：

- 缺点：用户需要知道自己正在看哪个 module，也可能需要切页。
- 优点：层次与边界更分明。每个 module 有明确空间，Goals 仍像 Goals，时间可以直接用数字，System 可以直接表达容量，不必为了统一被迫转换成同一种图表。

这种分层不是多余步骤。它也在帮助用户建立位置感，并控制一次进入视野的信息量。统一入口可以减少选择，清晰分层则可以减少理解；两者降低的是不同类型的摩擦。

对于时间，单纯数字可能就是最有效的表示。对于 Goals，圆环成立，但未必明显优于 `1/6`。对于 System，剩余空间圆环很自然，但文件分类与建议仍需要另一种结构。局部成立不等于值得重构整个 shell。

因此当前决策不是选中某个终极方案，而是承认两者确实存在 trade-off，并停止把一个尚未成为主要痛点的问题继续放大。

## Hover 的判断

如果未来重新讨论二级 popover，当前偏好是 hover，而不是强制点击。它应当紧邻一级入口、鼠标路径连续、不会跨空隙失焦，并允许用户自然进入二级面板。

这只是被保留的交互偏好，不是已批准的开发事项。

## 何时值得重新打开讨论

只有出现以下真实信号之一，才值得重新设计，而不是因为形式上可以更统一：

- 用户经常点错菜单栏入口，或明显不知道应该去哪个 module。
- module 增多后，现有翻页或直达方式形成持续摩擦。
- 一级 popover 的信息摄入量确实过大。
- 有完整视觉方案能证明统一摘要没有牺牲辨识度。
- 真实使用表明“打开一次，再 hover 深入”明显快于现有路径。

在这些信号出现前，保持现状就是设计决策本身。
