## 1. 用户目标

打开 Kaji 永远是安静的黑白灰；不再有「黑白 / 彩色」二选一，也不再出现 Calm 蓝或 Playful 绿。

一句话成功标准：

> 外观只跟系统 Light/Dark；没有 Color 开关，也没有第二套产品色。

## 2. 范围内（In）

1. 主题解析：**仅** `colorScheme` → `monoLight` / `monoDark`（对应 design-language 色板）
2. 删除 Settings 里 Black/White vs Color 分段开关及相关 L10n 入口（若仅本开关使用）
3. 删除 / 停用 `MenubarStyle` 的产品路径：`.color`、遗留 `.mono` 不再参与主题选择
4. 迁移：UserDefaults 里已存的 `.color` / `.mono` **一律当作** `.blackWhite`（或等价「已归一」）
5. 清理 `Palette.swift` 中 Calm / Playful 主题常量（或至少使任何 resolve 路径都到不了它们）
6. 菜单栏 glyph / popover / overlay / Settings 等凡调用 `KajiTheme.resolve` 或传 `MenubarStyle` 的地方，统一走 mono 路径（消掉「硬编码 `.blackWhite` 而别处仍读 prefs」的分叉）

## 3. 范围外（Non-goals）

本 spec **不做**：

- GitHub Release、版本号 bump
- 大改 README / 营销文案（**仅当**文案仍宣传 Color / Calm / Playful 时，删掉那一两处提及即可；不整篇重写）
- 改 lean modules、状态栏 Work 倒计时、Break 玩法
- 另做「外观」开关（Light/Dark 只跟系统）
- 重画 design-language 色值（以现有 `monoLight` / `monoDark` + design-language 表为准）
- Ice / 插件市场 / Pet 状态栏大件

## 4. 行为说明

### 4.1 主题 resolve

目标 API 形态（名字可微调，语义锁定）：

```text
resolve(colorScheme) → monoLight | monoDark
```

- `.light`（及非 dark）→ `monoLight`
- `.dark` → `monoDark`
- **不再**接受 `MenubarStyle` 作为主题分支参数

### 4.2 Prefs / 迁移

- 加载时：`menubarStyle` raw 为 `"color"` 或 `"mono"` → 归一为 `blackWhite`（并写回 UserDefaults，避免下次再读到旧值）
- 缺省 / 损坏 / 未知 raw → `blackWhite`
- **拍板方案 B**：保留内部枚举（仅 `.blackWhite` 有意义），无 UI 开关、无 `.color` 分支；加载时把旧 raw 归一并写回
- Settings **不得**再出现 Color 切换控件

### 4.3 菜单栏与 UI

- Status item / rings：一律按 mono 语义着色（跟系统 scheme），不再有「Color 模式绿弧」
- AppDelegate / StatusItemView 里为防 Color 而硬编码 `.blackWhite` 的临时分叉，本切片一并收干净

### 4.4 不变量

1. 任意 `ColorScheme` 下，resolve 结果只能是 mono 两套之一
2. 用户无法通过 prefs 选回 Calm / Playful / Color
3. 老用户曾选 Color，升级后外观变为 Mono，无迁移 toast（避免加戏）

## 5. 关键验收用例（人出题）

实现前，这些应先变成 **纯函数单元测试**（或抽到 `KajiCore` 的 normalize / resolve helper）。格式：给定 → 期望。


| # | 给定 | 期望 |
| --- | --- | --- |
| 1 | `normalizeMenubarStyle(nil)` / key 不存在 | `blackWhite`（或「已 mono-only」哨兵） |
| 2 | raw `"mono"` | 归一为 `blackWhite` |
| 3 | raw `"color"` | 归一为 `blackWhite` |
| 4 | raw `"blackWhite"` | 保持 `blackWhite` |
| 5 | raw 未知 / 损坏（如 `"rainbow"`） | 回退 `blackWhite` |

| 8 | 归一后写回：曾存 `"color"`，加载一次后再读 prefs key | 存的是 `blackWhite`（或 key 已删除且行为等同 mono） |

| # | 给定 | 期望 |

## 6. 验证策略

**原则：能稳定自动化的先自动化；人手只留给最终长相。**

| 层 | 本切片 | 谁跑 |
| --- | --- | --- |
| 单元（`swift test`） | §5 的 normalize / resolve（1–8，及选用 B1） | CI / agent / 本地一条命令 |
| 集成 | Prefs ↔ Settings 去开关 | 单元覆盖迁移写回即可；UI 接线不单开自动化 |
| E2E / UX | 「看起来是不是黑白灰、有没有绿/蓝」 | **仅维护者**：实现绿了之后短冒烟 |

手工冒烟（实现完成后一次即可）：

1. Settings 没有 Color 开关  
2. 系统 Light：popover / 环是 mono light  
3. 系统 Dark：mono dark  
4. 曾选过 Color 的 prefs（可手改 UserDefaults）启动后仍是 mono，重启后仍是
